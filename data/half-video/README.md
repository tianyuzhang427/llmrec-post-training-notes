# Half Video

Half Video 是一次面向训练预算的推荐数据清洗：只对“懂推荐”中的 Video 目标样本做覆盖度优先的下采样，电商、广告和直播样本全部保留。

这里的“清洗”不是重写文本、修正标签或按内容质量打分，而是删除冗余的 Video 行。所有保留样本都从官方 seed dataset 中逐字节复制，prompt、response 和标签均未改动。

## 为什么清洗 Video

原始“懂推荐”共有 19,204 条样本，其中 Video 占 14,868 条，即 `77.10%`。对应的 Video supervised tokens 为 10,068,437，也占据了推荐任务的大部分训练预算。

item-token loss 和 focal loss 的正向结果让我推测：seed dataset 中存在大量简单且重复的文本样本。Video 是“懂推荐”中占比最大的 domain，因此我首先从这里减少冗余，同时尽量保留用户历史、目标主题、SID、行为模式和 prompt 表面的多样性。

## 怎么清洗

1. 从 `懂推荐1.jsonl` 至 `懂推荐4.jsonl` 读取全部 19,204 条推荐样本，根据 response 末尾的目标 token 判断目标域。
2. 电商、广告和直播样本全部保留，只在 14,868 条 Video 样本中进行选择。
3. 第一阶段采用 coverage-first 贪心选择，优先覆盖以下维度：
   - 用户历史；
   - 目标 `s_a` 和目标三级主题；
   - 历史 cluster、目标主题及其组合；
   - 行为模式；
   - system prompt、instruction 表面和 response 长度桶。
4. 完成全量维度覆盖后，在 `history cluster × target topic` 分层内按原始规模分配剩余额度。
5. 填充时优先保留新的 `s_a+s_b`、新的完整 SID，并抑制相同用户历史和高频 `s_a` 的重复出现。
6. 使用固定随机种子 `20260719` 生成稳定排序，最终保留 7,434 条 Video 样本。

可以将构造过程简化为：

```text
Half Video
= 全部非 Video 推荐样本
+ coverage_first(Video, 7,434)
```

## 清洗前后

| 目标域 | 减半前 | 减半后 |
| --- | ---: | ---: |
| 视频 | 14,868 | 7,434 |
| 电商 | 1,489 | 1,489 |
| 广告 | 1,576 | 1,576 |
| 直播 | 1,271 | 1,271 |
| 合计 | 19,204 | 11,770 |

| 训练预算 | 减半前 | 减半后 |
| --- | ---: | ---: |
| Video supervised tokens | 10,068,437 | 5,026,092 |
| 全部推荐 supervised tokens | 13,059,178 | 8,016,833 |
| Video 在推荐数据中的行数占比 | 77.10% | 62.69% |

输出 JSONL 为 217.9 MB，gzip 后约 35.8 MB。文件行数不算大，但每条样本包含较长的跨域用户历史，因此原始体积较大。

## 验证与结果

构建完成后通过了以下检查：

- 电商、广告和直播的行数与 token 统计保持不变；
- 所有保留行与源数据逐字节一致；
- 用户历史、cluster、目标主题、目标三级主题、目标 `s_a`、行为模式、system、instruction 和长度桶均保持完整覆盖；
- Video 行数严格保留 50%，对应 supervised tokens 保留 `49.92%`。

50% 版本进入了后期高分配方，线上结果验证了这一清洗方向有效。继续降到 35% 时，只保留 5,204 条 Video 样本，已经非常接近 5,138 条的完整覆盖下限，留给分层比例和重复曝光的余量只有 66 条。该版本的线上收益转负，说明有效的是在保留必要覆盖和重复曝光的前提下适度去冗余，而不是持续压缩数据量。

需要注意，50% 版本所在的线上配方还同时包含 Math Plus、Item2 和 LogicChain → ActionSelect，因此现有结果支持“适度清洗 Video 是有效方向”，但不能单独估计 Half Video 对总分的因果贡献。
